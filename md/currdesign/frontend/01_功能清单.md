## 三、按"用户故事"验证覆盖度

对照 `panel_app.design.md` 的主链路，逐步检查前端能否支撑：

| 主链路步骤 | 前端能否支撑 | 缺口 |
|---|---|---|
| 1. 上传/录制哼唱 | ✅ 能 | 缺拖拽与进度（A8） |
| 2. 输入自然语言指令 | ✅ 能 | 缺快捷模板（A9） |
| 3. 看 AI 思考 | 🟡 部分 | reasoning 有，但**正文不流式**（A3） |
| 4. 看技能逐个执行 | 🔴 弱 | 只有灰色扁平 log，**没有工具卡片**（A5） |
| 5. 中途反悔想停 | 🔴 **不能** | 无中断按钮，后端也无取消通道（A6） |
| 6. 看产物文件 | 🔴 **不能** | 无文件树，无法预览/下载任意产物（B12） |
| 7. 试听生成结果 | 🔴 **不能** | 音频组件全是孤儿（C1/C2/C3） |
| 8. 手动改 MD 再迭代 | 🔴 **不能** | TrackEditor 保存不落盘（B10） |
| 9. 看工程诊断建议 | 🔴 **不能** | diagnosis 数据有，UI 没做（B13） |
| 10. 不想用 AI，手动点技能 | 🔴 **不能** | 技能面板 0 实现（D1-D3） |

> **结论：10 步主链路中，6 步走不通。** 其中 B10 / B12 / D1-D3 的后端接口都是现成的，属于纯前端欠账；A5 / A6 / A3 需要后端先接线 ReAct 与事件总线。
