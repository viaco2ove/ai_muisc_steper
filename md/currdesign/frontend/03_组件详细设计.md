> 只写**新增**和**需要改造**的组件。已达标组件（BasicInfo 只读态、ChordViz 单和弦、ExportPanel）不重复描述。

## 一、ToolCallCard（★ 最核心的新组件）

现状是把 `log` / `skill_done` 拍平成一条条灰色气泡，用户看不出"哪些日志属于哪个工具"。改为按 `call_id` 聚合的卡片。

### 视觉状态机

```
┌─ 🔧 audio_chord_recognizer            ⏱ 运行中 3.2s   [▾] ┐   running（蓝色左边框 + 呼吸动画）
│  参数  input: workspace/.../hum.wav                        │
│  ┌── 日志 ─────────────────────────────── [自动滚动 ✓] ┐  │
│  │ [librosa] loading audio...                          │  │
│  │ [beat] BPM=68.2                                     │  │
│  └──────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────┘

┌─ ✅ audio_chord_recognizer                     1.8s  [▸] ┐   ok（绿色，日志默认折叠）
│  产物  📄 chords.json   🎵 melody.mid   （点击→文件预览）  │
└──────────────────────────────────────────────────────────┘

┌─ ❌ musescore-cooperate                        0.4s  [▾] ┐   error（红色，自动展开）
│  参数  --project: 走在   --full: true                     │
│  Traceback (most recent call last): ...                   │
│                                          [重试] [复制报错] │
└──────────────────────────────────────────────────────────┘
```

### Props / 行为

```ts
interface ToolCallCardProps {
  node: Extract<StreamNode, { kind: 'toolcall' }>
  onRetry: (tool: string, args: Record<string, any>) => void
  onOpenFile: (path: string) => void
}
```

| 规则 | 说明 |
|---|---|
| 折叠默认值 | `running` 展开 / `ok` 折叠 / `error` 展开 |
| 日志自动滚动 | 用户手动上滚时**暂停自动滚动**并显示「回到底部」按钮（终端类组件通用做法） |
| 日志上限 | 单卡片 500 行，超出丢弃最早的并在顶部提示「已省略 N 行」 |
| 耗时 | `running` 时 `setInterval(100ms)` 实时跳数；结束后固定为 `endedAt - startedAt` |
| 参数展示 | 值超 80 字符折叠为 `path/to/....wav`，hover Tooltip 显示全量 |
| 产物 chip | 按扩展名配图标：`.mid`🎵 `.wav`🔊 `.mscx`🎼 `.md`📄 `.json`⚙️；点击 → 切到「文件」Tab 并预览 |
| 重试 | 仅 `error` 显示；携带原 `args` 走单技能执行通道（D3） |

### 日志批量刷新（关键性能点）

```ts
// 不要每条 log 都 setState
const buffer = useRef<string[]>([])
const flush = useCallback(() => {
  if (!buffer.current.length) return
  sessionStore.appendLogs(callId, buffer.current)
  buffer.current = []
}, [callId])
// wsClient 侧：收到 log 只 push buffer，rAF 里统一 flush
```

## 二、MessageStream

```ts
interface MessageStreamProps { nodes: StreamNode[] }
```

- 按 `node.kind` 分发到 `nodes/` 下的组件，每个都 `React.memo`。
- **粘底滚动**：`useAutoScroll` —— 距底 < 80px 时自动跟随；用户上滚则停止并显示「↓ 有新消息」。
- 节点数 > 200 时启用虚拟滚动（`@tanstack/react-virtual`，P3）。
- 空态：展示 PromptChips 快捷指令引导。

### AssistantBubble —— Markdown 渲染

```tsx
<ReactMarkdown
  remarkPlugins={[remarkGfm]}
  components={{
    code: CodeBlock,        // shiki 高亮 + 复制按钮
    table: MdTable,         // Tailwind 表格样式，AI 常输出和弦表
    a: ExternalLink,
  }}
>{text}</ReactMarkdown>
```
流式期间在文本尾部渲染闪烁光标 `▍`。

### ThoughtBlock —— 思考流

- `<details>` 折叠，**默认折叠**（现状默认展开，长思考会把正文顶到屏幕外）。
- 标题栏：`💭 思考中... (1.2s)` → 完成后 `💭 已思考 4.7s`，并**自动收起**。
- 内容 `max-h-64 overflow-auto`，等宽字体，弱化配色（琥珀色系保留）。

## 三、Composer（输入区）

```
┌──────────────────────────────────────────────────────┐
│ [🎤 录音] [📎 上传] [📄 引用文件]      🎵 hum.wav ✕   │
├──────────────────────────────────────────────────────┤
│ 分析这段哼唱，生成沙发小曲的完整主歌副歌和弦...        │
│                                                       │
├──────────────────────────────────────────────────────┤
│ 快捷: [生成副歌][丰富和弦][优化转音][导出OpenUTAU]     │
│                              Ctrl+Enter 发送  [ 发送 ]│
└──────────────────────────────────────────────────────┘
```

### 发送 / 停止 按钮状态机

| taskStatus | 按钮 | 行为 |
|---|---|---|
| `idle` | 「发送」蓝色，空输入时禁用 | `pushUser()` 乐观入列（修 BUG-2）→ `ws.send(chat)` |
| `thinking` / `running` | 「■ 停止」红色 | `ws.send({type:'cancel', task_id})`，状态转 `cancelling` |
| `cancelling` | 「停止中…」禁用 | 等后端 `task_done{cancelled:true}` |
| WS 断开 | 禁用 + 顶部横幅 | 提示重连进度 |

- **Esc** 快捷键等价点击停止。
- 输入区 `textarea` 自增高（1→8 行封顶）。
- 上传：支持**拖拽到整个 AgentPanel**（dragover 高亮遮罩）；前端校验扩展名（wav/mp3/flac/m4a）与大小（≤100MB）；上传中显示进度条。

## 四、WorkspacePanel（Tab 化改造）

现状 5 个板块堆在一个滚动条里。改为 Tab：

| Tab | 内容 | 说明 |
|---|---|---|
| **工程** | ProjectSwitcher / BasicInfo / SectionTable / ChordTimeline / DiagnosisPanel | 全局视图 |
| **分轨** | TrackList（左窄列） + TrackEditor（右主区） | 主从布局，替代现在的"二选一切换" |
| **文件** | FileTree + FilePreview | 新增 |
| **技能** | SkillList + SkillParamForm | 新增 |

底部常驻 ExportPanel。Tab 状态存 `uiStore` 并 persist。

### ProjectSwitcher

- 替换原生 `<select>` 为 Radix Select，条目显示：工程名 + 轨道数 + 更新时间。
- 右侧 `⋯` 菜单：新建 / 重命名 / 复制 / 删除（删除需输入工程名二次确认）。
- **切换前检查 `dirtyTracks`**，有未保存内容则拦截。

### NewProjectDialog（替代三连 `prompt()`）

| 字段 | 类型 | 校验 |
|---|---|---|
| 工程名 | text | 必填；禁止 `\ / : * ? " < > \|`；与已有工程重名时实时报错 |
| 风格 | select + 自定义 | 预设：沙发小曲 / Lo-Fi / 民谣 / 流行 / City Pop |
| BPM | number | 40–240，默认 68 |
| 调性 | select | 12 大小调，默认 C |
| 拍号 | select | 4/4、3/4、6/8，默认 4/4 |

## 五、TrackEditor（改造，修 BUG-3）

### 必修：保存真正落盘

```ts
const save = async () => {
  setSaving(true)
  try {
    await projectStore.saveTrack(trackId, md)   // → PUT /api/project/{name}/track/{id}
    projectStore.clearDirty(trackId)
    toast.success('已保存')
  } catch (e) {
    toast.error(`保存失败：${e.message}`)       // 不再是 alert()
  } finally { setSaving(false) }
}
```

### 编辑器升级

| 项 | 方案 |
|---|---|
| 编辑器 | CodeMirror 6 + `lang-markdown`（比 Monaco 轻 10 倍，够用） |
| 布局 | 左编辑 / 右实时预览，可切换为纯编辑 |
| 状态条 | `● 未保存` / `✓ 已保存 14:32` / 行列号 / 字数 |
| 快捷键 | `Ctrl+S` 保存（保留）、`Ctrl+/` 注释 |
| 脏检查 | 有改动即 `markDirty(trackId)`；切轨/切工程/关页面拦截 |
| 保存失败 | 保留本地内容不回滚，卡片提示「重试」 |
| 冲突处理 | 保存时带 `updated_at`；后端检测到文件已被技能改写则返回 409，前端弹「本地/远端」对比选择 |

> 冲突场景真实存在：AI 跑完 `song_engineer` 会重写轨道 MD，此时用户编辑框里是旧内容，直接保存会覆盖 AI 成果。

## 六、FileTree + FilePreview（★ 新增）

### FileTree

数据源 `GET /api/project/{name}/files` → `[{path, type, size, time}]`（后端已有）。

- 前端按 `path` 拆分构造树；按目录分组：`song_engineer/` `track/` `ai-track/` `musescore/` 根目录散件。
- 每行：图标 + 文件名 + 大小 + 相对时间（"3 分钟前"）。
- **新产物高亮**：`artifact` 事件带回的 path 在树上闪烁 3 秒并自动展开父目录。
- 右键菜单：预览 / 下载 / 复制路径 / 在资源管理器中显示（Electron 阶段）。

### FilePreview（按扩展名分发）

| 扩展名 | 预览方式 |
|---|---|
| `.md` | react-markdown 渲染 |
| `.json` | 折叠 JSON 树 + 高亮 |
| `.txt` `.lrc` | 纯文本（等宽） |
| `.wav` `.mp3` | **AudioPlayer + WaveformView**（接线 C1/C2） |
| `.mid` | **MidiPreview 钢琴卷帘**（接线 C3） |
| `.mscx` | 不预览，提供「用 MuseScore 打开」（Electron 阶段）+ 下载 |
| 其他 | 显示元信息 + 下载按钮 |

> **后端依赖（当前缺失）**：需要 `GET /api/project/{name}/file?path=xxx`，且要能以 `Range` 方式供 `<audio>` 拖动。详见 `04_后端支撑改造.md`。

## 七、SkillList + SkillParamForm（★ 新增，可视化 CLI）

数据源 `GET /api/skills`（后端已有，返回 `name/description/params/executable/entry_script`）。

### SkillList
- 分两组：**可执行**（`executable:true`，可点击运行）/ **提示词技能**（`executable:false`，灰显，标注"需经 AI 调度"）。
- 搜索框 + 收藏（★）+ 最近执行。
- 卡片：技能名 / 描述（一行截断）/ 参数数量 / `[运行]` 按钮。

### SkillParamForm（由 `params` 动态生成）

后端 `params` 是 JSON，如 `{"--project": "歌曲名(required)", "--tracks": "逗号分隔轨道", "--full": "生成总谱"}`。

**推断规则**：

| 描述特征 | 控件 | 示例 |
|---|---|---|
| 含 `(required)` | 必填标记 + 校验 | `--project` |
| 参数名含 `project` | 工程下拉（自动填当前工程） | `--project` |
| 描述含 `路径` / `文件` | 文件选择器（走上传或从 FileTree 挑） | `--input`、`--midi` |
| 描述含 `(default xxx)` | 输入框 placeholder 填默认值 | `--track` |
| 描述以"生成/是否"开头且无值 | Checkbox（flag 型） | `--full` |
| 其他 | 文本输入 | — |

执行后走 WS 通道，日志复用 ToolCallCard 渲染（与 AI 调度视觉一致）。

> ⚠️ **前置依赖**：`ai_chords_master`、`karplus-strong`、`musicgen-stereo-melody` 三个技能**没有 frontmatter**，`remix-master` 的 frontmatter 是 GBK 乱码。这些技能在面板里会缺失或显示乱码，必须先补齐（见 `04` 文档）。

## 八、DiagnosisPanel（★ 新增）

`song_engineer.json` 的 `diagnosis` 字段已有数据，前端完全没渲染 —— 这是 `song_engineer` 技能的核心产出，白白浪费。

- 五维评分 → SVG 雷达图（完成度 / 一致性 / 编曲丰富度 / 人声适配 / 混音就绪度，具体维度以实际字段为准）。
- 建议列表：按严重度分级（🔴阻断 / 🟡建议 / 🔵优化），每条带「让 AI 修复」按钮 → 把建议文本填进 Composer 并聚焦。
- 顶部「重新诊断」→ 触发 `song_engineer` 技能。

## 十一、UI 基建组件

### Toast（替代所有 `alert()`）
- 右上角堆叠，`success / error / info / loading` 四态，3s 自动消失（error 5s）。
- 长任务用 loading toast，完成后原地转 success。

### ErrorBoundary
- 分三层：App 级（全屏兜底）、Panel 级（左右各一，只塌陷单侧）、Card 级（单个 ToolCallCard 渲染失败不影响其他）。
- 错误页展示 `error.message` + 「复制诊断信息」+「重载此面板」。

### Skeleton
- 工程加载：BasicInfo 六宫格灰块 + 表格三行灰条。
- 替代现在的纯文字 "加载中..."。
