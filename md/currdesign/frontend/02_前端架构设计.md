# 02 · 前端架构设计

---

## 一、设计原则

1. **前端不做运算**（`agent_panel.design.md` 明确）：不解析 MD、不跑技能、不算乐理。所有结构化数据由后端 `song_engineer.json` 提供。
   → 推论：`utils/mdParser.ts` 这类"前后端同逻辑"的重复实现应当**删除**，避免两套解析器漂移。
2. **事件驱动渲染**：对话区不是"消息数组"，而是**事件流的投影**。后端推 `thought / action / log / observation / text / artifact / error`，前端按 `call_id` 聚合成卡片。
3. **单一数据源**：工程数据只有一份 `projectData`（来自 `song_engineer.json`），任何编辑走"提交 → 后端重解析 → 回写 store"，不做前端本地推导。
4. **可中断**：任何长任务都要有 `task_id`，前端随时能发 `cancel`。
5. **降级可用**：WS 断开时，REST 功能（浏览工程、技能面板、导出）仍可用。

## 五、状态管理设计

### 5.1 sessionStore —— 对话即事件流

**核心思路**：不存"消息数组"，存**事件节点数组**，工具调用按 `call_id` 就地合并。

```ts
// types/events.ts —— 与后端 EventType 严格对齐
type AgentEventType =
  | 'thought' | 'text' | 'action' | 'log'
  | 'observation' | 'artifact' | 'error'
  | 'task_start' | 'task_done'

interface AgentEvent {
  type: AgentEventType
  task_id: string
  call_id?: string          // 工具调用关联键
  seq: number               // 单调递增，用于乱序保护
  payload: any
}

// 渲染节点（事件投影后的结果）
type StreamNode =
  | { kind: 'user';      id: string; text: string; audioPath?: string }
  | { kind: 'assistant'; id: string; text: string; streaming: boolean }
  | { kind: 'thought';   id: string; text: string; streaming: boolean }
  | { kind: 'toolcall';  id: string; callId: string
      tool: string; args: Record<string, any>
      logs: string[]                       // 实时追加
      status: 'running'|'ok'|'error'
      files: string[]; output?: string; error?: string
      startedAt: number; endedAt?: number }
  | { kind: 'error';     id: string; text: string }

interface SessionStore {
  nodes: StreamNode[]
  taskId: string | null
  taskStatus: 'idle' | 'thinking' | 'running' | 'cancelling'
  wsStatus: 'connecting' | 'connected' | 'disconnected'

  pushUser(text: string, audioPath?: string): void   // 乐观更新，修 BUG-2
  applyEvent(e: AgentEvent): void                    // 事件 → 节点投影
  cancelTask(): void
  clear(): void
}
```

**`applyEvent` 投影规则**

| 事件 | 处理 |
|---|---|
| `task_start` | 记 `taskId`，`taskStatus='thinking'` |
| `thought` | 找尾部 `streaming` 的 thought 节点追加；无则新建 |
| `text` | 找尾部 `streaming` 的 assistant 节点追加；`done` 时 `streaming=false` |
| `action` | **新建 toolcall 节点**，`status='running'`，记 `startedAt` |
| `log` | 按 `call_id` 找到 toolcall 节点，push 进 `logs`（超 500 行截头） |
| `observation` | 按 `call_id` 更新 `status/output/error/endedAt` |
| `artifact` | 按 `call_id` 填 `files`；同时触发 `projectStore.refresh()` |
| `error` | 若有 `call_id` 则标该卡片失败，否则新建 error 节点 |
| `task_done` | `taskStatus='idle'`，收尾所有 streaming 节点 |

> **乱序与丢包保护**：事件带 `seq`，store 维护 `lastSeq`；若 `seq` 跳变，标记该轮"可能丢事件"并在任务结束后触发一次 `GET /api/project/{name}` 全量对账。

### 5.2 projectStore

```ts
interface ProjectStore {
  projects: ProjectBrief[]
  currentName: string | null        // ★ 修 BUG-1，必须被写入
  data: ProjectData | null          // song_engineer.json
  tracks: Record<string, TrackDetail>   // 轨道详情缓存
  dirtyTracks: Set<string>          // ★ 未保存标记，切换轨道时拦截
  loading: boolean; error: string | null

  select(name: string): Promise<void>   // ← 必须同时写 currentName + 拉数据
  refresh(): Promise<void>              // artifact/project_updated 时调
  loadTrack(id: string): Promise<void>
  saveTrack(id: string, md: string): Promise<void>   // ★ 真正落盘，修 BUG-3
  create(payload: NewProjectPayload): Promise<void>
  remove(name: string): Promise<void>
}
```

**脏数据保护**：`dirtyTracks` 非空时，切换轨道/工程/关闭页面弹二次确认。当前版本切走即静默丢失。

### 5.3 skillStore / uiStore
```ts
interface SkillStore {
  skills: SkillMeta[]              // GET /api/skills
  favorites: string[]              // localStorage
  recent: { tool: string; args: any; at: number }[]
```

## 六、通信层设计

### 6.1 统一入口（修 BUG-4）

```ts
// transport/rest.ts
const BASE = import.meta.env.VITE_API_BASE ?? ''   // 默认空 → 相对路径 → 走 proxy
// transport/wsClient.ts
const WS_URL = import.meta.env.VITE_WS_URL
  ?? `${location.protocol === 'https:' ? 'wss' : 'ws'}://${location.host}/ws/chat`
```

配套 `frontend/.env.development`：
```
VITE_API_BASE=
VITE_WS_URL=
```
Electron 打包时才通过 `.env.production` 指向 `http://127.0.0.1:{动态端口}`。

> **必须同步统一端口**：后端 `config.py` 默认 8000、`.env.example` 8120、`vite.config.ts` proxy 8120。建议**统一为 8000**，并让 `vite.config.ts` 读 `process.env.BACKEND_PORT`。

### 6.2 wsClient 能力

| 能力 | 设计 |
|---|---|
| 心跳 | 每 25s 发 `{type:'ping'}`；60s 未收 `pong` 判定死连接主动重连（现状只被动处理 `onclose`） |
| 重连 | **指数退避** 1s→2s→4s→8s→最大 30s，上限 10 次；恢复后发 `{type:'resync', task_id}` 询问是否有进行中任务 |
| 发送队列 | 未连接时消息入队，连上后 flush（现状只 `console.warn` 丢弃） |
| 取消 | `cancel(taskId)` 发 `{type:'cancel', task_id}` |
| 单例 | 模块级单例，React StrictMode 双挂载不会开两条连接（现状用 `storeRef` 规避，较脆） |

## 七、渲染性能

| 场景 | 风险 | 方案 |
|---|---|---|
| 技能日志刷屏（mscx 生成上千行） | 每行一次 setState → 卡死 | **16ms 批量合并**：日志入 buffer，`requestAnimationFrame` 统一 flush；单卡片保留最近 500 行 |
| 消息流长列表 | 节点多时重渲染 | 节点组件 `React.memo`，key 用稳定 id；超 200 节点启用虚拟滚动 |
| 打字机流式 | 每 token 一次全量重渲 | 只更新尾部 streaming 节点，其余 memo 命中 |
| 钢琴卷帘 | Canvas 重绘 | 离屏 Canvas 缓存静态音符层，只重绘播放头 |

## 八、错误与降级

| 故障 | 表现 | 降级 |
|---|---|---|
| WS 断开 | Header 状态灯变红 + Composer 顶部横幅"连接已断开，重连中(3/10)" | 禁用发送；REST 功能（浏览/导出/技能列表）仍可用 |
| 后端未启动 | 首屏 `GET /api/health` 失败 | 全屏引导页："后端未运行，请执行 `start_workbench.bat`" |
| 技能执行失败 | ToolCallCard 变红 + 展开 stderr | 卡片提供「重试」按钮（携原参数重发） |
| 工程 JSON 缺字段 | 保留现有多路兜底（`basic/meta`、`id/track_id/name`） | 缺字段显示 `—` 而非崩溃 |
| 组件抛错 | ErrorBoundary 兜住 | 只塌陷该面板，不白屏；提供「重载此面板」 |
