# 04 · 后端支撑改造方案

> 前端每一项 P0/P1 功能都在这里能找到对应的后端支撑项。
> **核心发现：`backend/app/core/` 下已经写好了一整套 v2 骨架（ReAct / 工具注册 / 沙盒 / 中断 / 事件），但没有任何一处被 `main.py` 或 `api/` import。** 运行时仍走 v1 的 `agent_core + llm_agent`。所以大部分改造是**接线 + 修 bug**，不是从零写。

## 二、WebSocket 协议 v2（最关键）

### 2.1 现状协议的问题

| 问题 | 后果 |
|---|---|
| 无 `task_id` | 前端无法关联一轮任务，无法取消 |
| 无 `call_id` | 日志不知道属于哪个工具调用 → 做不了 ToolCallCard |
| 无 `seq` | 乱序/丢包无感知 |
| 无上行 `cancel` | 做不了停止按钮 |
| `text` 一次性发 `stream:true, done:true` | 字段名骗人，实际不是流式 |
| 用 `role:"user_echo"` 回显用户消息 | 前端应乐观更新，这是绕过 bug 的错误方案 |
| `llm_raw` 事件截断 200 字符塞进 log | 调试信息污染用户视图 |

### 2.2 上行消息（前端 → 后端）

```ts
{ type: "chat", task_id: string, msg: string,
  project?: string, audio_path?: string,
  history?: {role, content}[] }

{ type: "cancel",  task_id: string }              // ★ 新增
{ type: "run_skill", task_id: string,             // ★ 新增：单技能直连（D3）
  tool: string, args: Record<string, any>, project?: string }
{ type: "resync",  task_id?: string }             // ★ 新增：重连后询问进行中任务
{ type: "ping" }
```

> `task_id` 由**前端生成**（uuid），后端原样回带。这样取消请求不必等后端先返回 id，避免"任务刚起就点停止"的竞态。

### 2.3 下行事件（后端 → 前端）

统一信封，对齐 `core/schemas/events.py` 的 `EventType`：

```ts
interface AgentEvent {
  type: 'task_start'|'thought'|'text'|'action'|'log'
      | 'observation'|'artifact'|'error'|'task_done'|'pong'
  task_id: string
  seq: number            // 该 task 内单调递增
  call_id?: string       // 工具类事件必带
  ts: number             // 毫秒时间戳
  payload: object
}
```

| type | payload | 前端消费 |
|---|---|---|
| `task_start` | `{project}` | 状态转 `thinking`，禁用发送、显示停止 |
| `thought` | `{delta: string, done?: bool}` | 追加到 ThoughtBlock |
| `text` | `{delta: string, done?: bool}` | **改为增量**，追加到 AssistantBubble（A3） |
| `action` | `{tool, args, index, total}` | **新建 ToolCallCard** |
| `log` | `{line: string}` | 按 call_id 追加到卡片终端 |
| `observation` | `{status:'ok'\|'error', output?, error_stack?, duration_ms}` | 更新卡片状态 |
| `artifact` | `{files: [{path, size, type}], project}` | 卡片产物 chips + 触发 FileTree 刷新 |
| `error` | `{msg, call_id?, fatal: bool}` | 卡片红/独立 ErrorBlock |
| `task_done` | `{status:'success'\|'error'\|'cancelled', steps, duration_ms}` | 状态转 `idle`，收尾流式节点 |

**兼容策略**：`events.py` 里已有 `LEGACY_TYPE_MAP`，改造期后端**同时**推 v1（`chain_start`/`skill_done`/`chain_done`）和 v2 事件，前端按 v2 优先、v1 兜底。前端切换完成后移除 v1。

### 2.4 后端实现要点

```python
# app/core/event_bus.py（新写，~80 行）
class EventBus:
    def __init__(self, ws_send: Callable, task_id: str):
        self._send, self._task_id, self._seq = ws_send, task_id, 0
    async def publish(self, type_: EventType, payload: dict, call_id: str | None = None):
        self._seq += 1
        await self._send({
            "type": type_.value, "task_id": self._task_id,
            "seq": self._seq, "call_id": call_id,
            "ts": int(time.time() * 1000), "payload": payload,
        })
```

替换现在层层透传的 `ws_send` 闭包 —— 一处加 `seq`/`task_id`，全链路自动带上。

## 三、中断能力（支撑 A6 停止按钮）

### 问题
`AgentCore.run_skill` 是**同步阻塞 `subprocess`**，即便收到 cancel 也无法打断；`interrupt_token.py` 的类写好了但没人用。

### 改造

**1. WS 层维护任务表**
```python
# main.py
active_tasks: dict[str, InterruptToken] = {}

# 收到 chat：token = InterruptToken(); active_tasks[task_id] = token
# 收到 cancel：
tok = active_tasks.get(msg["task_id"])
if tok: tok.cancel()      # 触发已注册的 kill 回调
```

**2. `run_skill` 改异步**

现在是 `subprocess.run(...)` 同步阻塞，改为 `asyncio.create_subprocess_exec` + 逐行读 stdout（`sandbox_executor.py` 里**已经写好这套逻辑**）：

```python
process = await asyncio.create_subprocess_exec(*cmd, stdout=PIPE, stderr=STDOUT, env=env)
interrupt_token.register_callback(lambda: process.kill())
while True:
    line = await process.stdout.readline()
    if not line: break
    await bus.publish(EventType.LOG, {"line": line.decode('utf-8','replace').rstrip()}, call_id)
```

副产品：**日志真正实时了**。现状同步 `subprocess` 下日志是攒完一起吐的。

**3. ⚠️ 先修 `sandbox_executor.py` 的缩进 bug**

第 97–149 行全部落在 `except FileNotFoundError` 的 `return` 之后，成功路径不可达，`execute()` 实际返回 `None`。接线前必修，否则一接就炸。

**4. 中断语义**
- Kill 当前子进程 → 不再执行后续 step → 推 `task_done{status:'cancelled'}`。
- **不回滚已生成的文件**（技能可能已写盘），在 `task_done` 里带 `partial_files` 让前端提示"已生成部分产物"。
- Windows 下 `process.kill()` 只杀直接子进程；技能若再起孙进程（如 MuseScore4.exe）需用 job object 或 `taskkill /T /F`。**建议 Windows 走 `CREATE_NEW_PROCESS_GROUP` + `taskkill /PID xx /T /F`**。

## 四、ReAct 循环接线（支撑 A5 工具卡片 + 多步自纠错）

### 现状 vs 目标

```
现状（v1，单轮）:
  用户 → LLM(prompt里写死技能清单) → 正则抠 {need_tool, task_chain}
       → 串行跑完 → 结束。工具结果不回灌模型，无自纠错。

目标（v2，ReAct）:
  用户 → LLM(native tools schema) → tool_calls
       → 沙盒执行 → 结果作为 role:"tool" 回灌 → 再次 LLM
       → 循环直到无 tool_calls 或达 max_steps(15)
```

### 落地步骤

1. **`llm_client.chat_stream` 支持 tools 参数**
   现在请求体只有 `model/messages/stream/temperature`。需加 `tools` + `tool_choice:"auto"`，并解析流式 `delta.tool_calls` 的分片累加（arguments 是逐段拼接的 JSON 字符串，需缓冲）。

2. **接 `tool_registry.get_openai_tools_schema()`**
   代码已写好，删掉 `llm_agent.SYSTEM_PROMPT` 里硬编码的技能清单字符串。

3. **新写 `app/core/agent_loop.py`**
   骨架在 `md/currdesign/agent_core/agent_core.md` 里已给出完整代码，直接落地即可。

4. **降级兜底**
   本地模型 `orcg` 若不支持 native function calling，`LLMRegistry` 按模型能力路由：支持 → ReAct；不支持 → 保留现有 JSON 解析路径。**两条路径都走同一套 EventBus 事件**，前端无感知。

> 前端为什么依赖这个：只有 native `tool_calls` 才有稳定的 `call_id` 和结构化 `args`。现在从正则抠出来的 JSON 没有 id，无法把后续 log 关联到卡片。

## 五、正文流式（支撑 A3 打字机）

`llm_agent` 现在把 content 攒完再一次性 `{stream:true, done:true}` 发出。改为边收边推：

```python
async for kind, delta in llm.chat_stream(messages, tools=tools):
    if kind == "reasoning":
        await bus.publish(EventType.THOUGHT, {"delta": delta})
    elif kind == "content":
        await bus.publish(EventType.TEXT, {"delta": delta})     # ★ 逐 token
await bus.publish(EventType.TEXT, {"delta": "", "done": True})
```

注意：ReAct 场景下模型可能**先输出一段文字再调工具**，此时 `text` 不 `done`，等下一轮继续追加到同一个 assistant 节点。前端 `applyEvent` 已按此设计。

## 六、新增 REST 接口

### 6.1 文件读取（★ 支撑 B12 文件树 + C1/C2/C3 媒体预览）

当前最大的接口缺口：`list_files` 返回了 path，但**没有任何接口能读到内容**；`export` 只能按类型取 mtime 最新的一个。

```
GET /api/project/{name}/file?path={相对路径}&mode=raw|text
```
| 要求 | 说明 |
|---|---|
| **路径穿越防护** | `Path(project_dir/name/path).resolve()` 必须仍在工程目录内，否则 403。**这是必须做的**，否则 `?path=../../../.env` 直接泄露 API Key |
| **Range 支持** | 音频拖动进度条依赖 `206 Partial Content`。用 `FileResponse` + `Range` 中间件，或直接静态挂载 |
| **Content-Type** | 按扩展名推断，`.mid` → `audio/midi`，`.mscx` → `application/xml` |
| **大小上限** | `mode=text` 时超过 1MB 截断并返回 `truncated:true` |

**更简方案**：直接 `app.mount("/files", StaticFiles(directory=workspace/project))`，但这样**丢失越权校验**。建议走接口。

### 6.2 工程 CRUD 补齐

| 接口 | 用途 | 前端功能 |
|---|---|---|
| `DELETE /api/project/{name}` | 删除工程（移到 `.trash/` 而非真删） | B3 |
| `PATCH /api/project/{name}` body `{new_name}` | 重命名 | B3 |
| `POST /api/project/{name}/duplicate` | 复制工程 | B3 |
| `PUT /api/project/{name}/basic` body `{key,bpm,style,mood,...}` | 编辑基础信息 | B5 |
| `PUT /api/project/{name}/sections` body `{sections:[...]}` | 编辑段落表 | B7 |
| `POST /api/project/{name}/track` / `DELETE .../track/{id}` | 增删轨道 | B9 |

**写冲突保护**：`PUT` 类接口接受可选 `if_unmodified_since`（文件 mtime）。不匹配返回 **409** + 当前服务端内容，前端弹对比选择（对应 `03` 文档 TrackEditor 冲突处理）。

### 6.3 其他

| 接口 | 用途 |
|---|---|
| `GET /api/health` | 已有。前端首屏探活，失败显示"后端未运行"引导页 |
| `POST /api/project/{name}/render` | 触发 MuseScore 渲染全曲 mp3（支撑 C6 全曲预览） |
| `GET /api/skills` | **已有**，前端直接用（D1） |
| `POST /api/skill/{tool}` | **已有但同步无流式**；建议前端改走 WS `run_skill`，此接口保留给脚本调用 |

## 七、技能契约修数据（支撑 D1/D2 技能面板）

前端动态参数表单完全依赖 `SKILL.md` frontmatter。实测问题：

| 技能 | 问题 | 修法 |
|---|---|---|
| `ai_chords_master` | **无 frontmatter**（主链路核心技能！） | 补 `name/description/executable:false` |
| `karplus-strong` | 无 frontmatter | 补，`entry_script: generate.py`，`executable:true` |
| `musicgen-stereo-melody` | 无 frontmatter；且描述文不对题（写的是 Karplus-Strong） | 补 + 订正描述 |
| `remix-master` | frontmatter **GBK 乱码**（`閰嶇疆椹卞姩娣烽煶鎶€鑳姐€俙） | 用 UTF-8 重写 |
| `song_engineer` | 描述是"工程聚合诊断"，`entry_script` 却指向 `export_track_to_midi.py` | 二者对齐；若一个技能有多个脚本，扩展契约支持 `commands: [{name, script, params}]` |

- 新增 `GET /api/skills/validate` 返回契约体检报告，前端在技能面板顶部提示"3 个技能契约不完整"。

## 八、配置与部署

### 8.1 端口统一（修 E1）
三处不一致：`config.py` 默认 **8000** / `.env.example` **8120** / 前端硬编码 **8120**。

- 统一为 **8000**，`.env.example` 同步。
- `vite.config.ts` 的 proxy target 改读 `process.env.BACKEND_PORT ?? 8000`。
- 另：`config.py` 加载 `ROOT/.env`，`run.py` 加载 `backend/.env` —— **两个位置**，容易出现"改了没生效"。统一为 `ROOT/.env`。

### 8.2 静态托管（生产 / Electron）
```python
dist = ROOT / "frontend" / "dist"
if dist.exists():
    app.mount("/assets", StaticFiles(directory=dist / "assets"))
    @app.get("/{full_path:path}")   # SPA fallback，必须放在所有 /api 路由之后
    async def spa(full_path: str): return FileResponse(dist / "index.html")
```
配合前端相对路径，同源后 CORS 也不再需要（现在 `cors_origins` 里带了 `*`，生产环境应收紧）。
