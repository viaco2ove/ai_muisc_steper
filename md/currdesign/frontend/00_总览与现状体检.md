## 一、一句话结论

前端**骨架已搭完，血肉严重缺失**。左右分栏、WS 连接、工程读取、和弦可视化都跑通了，但存在 **4 个致命断链 bug** 让部分功能实际不可用；同时对照 `agent_core.md` 定义的 ReAct/事件流规范，前端**缺少全部 Agent 化交互能力**（工具卡片、中断、正文流式）。

根因不全在前端：后端 `core/` 里 **ReAct/沙盒/中断/工具注册 的 v2 骨架代码已经写好，但一行都没有接线**，运行时仍走 v1 的「Prompt 塞技能清单 → 正则抠 JSON → 单轮串行执行」。前端做不了 Agent 化 UI，是因为后端没有事件源。

## 三、🔥 4 个致命断链 Bug（必须最先修）

这几个不是"功能缺失"，是**已写的代码接错了线**，修复成本极低但收益极高。

### BUG-1｜`currentProject` 永远是 null → 轨道详情永远打不开
`store/projectStore.ts` 定义了 `selectProject`，但**全项目零调用**。`WorkspacePanel.handleSelectProject` 只调了 `loadProjectData`，没写 `currentProject`。

连锁后果：
- Header 不显示当前工程名
- `handleSelectTrack` 开头 `if (!currentProject) return` → **点任何轨道都没反应**
- ChatPanel 发 WS 消息时 `project` 字段永远为空 → 后端拿不到工程上下文

### BUG-2｜用户发的消息不进消息列表
`store.sendChat` 和 `useWebSocket.sendChat` **同名不同职责**。ChatPanel 只调了 hook 版（负责发 WS），没调 store 版（负责 `addChat`）。用户输入发出去后气泡直接消失，只能看到 AI 回复。

> 注：后端其实会回一条 `role:"user_echo"` 的 text 做回显，属于用错误的方式绕过错误 —— 用户消息应由前端乐观更新，不该等服务端回声。

### BUG-3｜TrackEditor 编辑内容不落盘
`TrackEditor.onSave` 只调用了 `setTrackMd` 更新本地 state，**从未调用 `api.saveTrack()`**。`services/api.ts` 里 `saveTrack` 函数定义了但零引用。用户辛苦编辑的 MD，切换轨道即丢失。

### BUG-4｜vite proxy 形同虚设
`vite.config.ts` 的 `/api` 和 `/ws` proxy 配置完备，但 `services/api.ts` 硬编码 `http://127.0.0.1:8120`、`useWebSocket` 硬编码 `ws://127.0.0.1:8120/ws/chat`，**都绕过了 proxy**。只有 ExportPanel 用了相对路径。后果：换端口/换机器/打包 Electron 全部失效。

> 顺带：后端 `config.py` 默认端口是 **8000**，`.env.example` 写的是 **8120**，前端硬编码 **8120** —— 三处不一致，新人克隆下来大概率跑不通。

## 五、后端侧的 3 个卡点（前端做不了 Agent UI 的根因）

| 卡点 | 现状 | 挡住了哪些前端功能 |
|---|---|---|
| **无取消通道 + 同步阻塞执行** | WS 无 `cancel` 消息；`AgentCore.run_skill` 是同步 `subprocess`，`interrupt_token.py` 类写好了但没接线 | 「停止生成」按钮、任务暂停 |
| **正文非流式** | `reasoning` 是真流式，但正文 content 攒完一次性 `stream:true, done:true` 发出 | 打字机效果 |
| **无按路径读文件 / 无静态托管** | `list_files` 返回了 path，但没有配套读取接口；`export` 只能按类型取 mtime 最新的一个 | 工程文件树、产物预览、指定文件下载 |

好消息：这三项的后端骨架 **`interrupt_token.py` / `file_service.py` / `tool_registry.py` + `sandbox_executor.py` 代码都已存在**，只差接线。

⚠️ 但 `sandbox_executor.py` 有个**缩进 bug**：第 97–149 行全部落在 `except FileNotFoundError` 的 `return` 之后，成功路径不可达，`execute()` 实际返回 `None`。接线前必须先修。

## 六、技能契约的坑（影响"技能面板"功能）

前端要做技能列表 + 动态参数表单，依赖 `SKILL.md` frontmatter。实测 22 个技能里：

| 问题 | 技能 | 影响 |
|---|---|---|
| **完全没有 frontmatter** | `ai_chords_master`、`karplus-strong`、`musicgen-stereo-melody` | Agent Core 扫不到，LLM 调不了，前端列不出来 |
| **frontmatter 是 GBK 乱码** | `remix-master`（`description: 閰嶇疆椹卞姩娣烽煶鎶€鑳姐€俙） | 前端展示乱码，LLM 读不懂用途 |
| **entry_script 与描述错配** | `song_engineer`（描述是"工程聚合诊断"，entry_script 却指向 `export_track_to_midi.py`） | 调用后行为与预期不符 |

> `ai_chords_master` 是设计文档里点名的核心链路技能（哼唱→和弦），却因为没 frontmatter 而不可调度 —— 这是主链路的硬伤。
